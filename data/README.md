# داده‌ها — سینک یک‌جا روی هر سیستم

این پوشه همهٔ دادهٔ شبیه‌سازی‌شدهٔ سامانه را نگه می‌دارد تا روی هر ماشین تازه، با یک فرمان، دقیقاً همین داده‌ها برقرار شود.

## محتوا

| مسیر | توضیح |
|---|---|
| `example/` | اسنپ‌شات کامل JSON از کل دیتابیس دمو (به‌جز بانک سوال) شامل استخر منابع — توسط `bun run db:export:example` تولید می‌شود |
| `sync-example-data.ts` | اسکریپت سینک یک‌جا (همان چیزی که این‌جا توضیح داده می‌شود) |
| `manifest.json` (داخل example) | تاریخ خروجی + تعداد ردیف هر جدول |

مشخصات فعلی اسنپ‌شات: **۵۰ دانش‌آموز**، ۵۱ کاربر (۱ مشاور + ۵۰ دانش‌آموز)، ۸ گروه هم‌پایه (هر گروه فقط یک پایه/رشته)، ۴۴۳ برنامهٔ هفتگی، ۱۶٬۴۸۵ تسک، تقویم مدرسه، آزمون‌های آزمایشی و آزمون‌های روان‌شناسی. رمز همهٔ کاربران نمونه: `seemorgh123`.

## سینک سریع روی سیستم جدید

```bash
bun install
bun run db:sync        # دیتابیس را از صفر می‌سازد و همهٔ داده‌ها را می‌ریزد
bun run dev
```

همین. اسکریپت شش کار انجام می‌دهد:

1. **import کامل `data/example/`** — ساخت اسکیمای PGlite و بارگذاری همهٔ ۳۲ جدول (درج‌ها idempotent هستند؛ ردیف تکراری skip می‌شود).
2. **استخر منابع** — بیش از ۴۰۰ کتاب/منبع کمک‌آموزشی با فصل‌بندی کامل؛ ابتدا بر اساس رشته (تجربی/ریاضی/انسانی) و سپس بر اساس درس گروه‌بندی می‌شود.
3. **هم‌تراز کردن منابع دانش‌آموزان با استخر** — عنوان، نوع واحد و فصل‌بندی هر منبع دقیقاً از کتاب استخر گرفته می‌شود؛ نسبت پیشرفت قبلی حفظ می‌شود. دیگر منبع بدون فصل‌بندی وجود ندارد.
4. **تکمیل منابع دروس برنامه** — هر درسی که در برنامهٔ هفتگی آمده منبع دارد؛ اگر نبود از استخر اضافه یا شبیه‌سازی می‌شود.
5. **بانک سوال تالیفی** — ۶۸ سوال نمونهٔ خود سامانه (`seed-question-bank`).
6. **بانک سوال منتا** — حدود ۱۵۰ هزار سوال از خروجی اسکرپ منتا، فقط اگر فایل `.monta/import/all-questions.jsonl` موجود باشد؛ در غیر این صورت این مرحله با هشدار رد می‌شود.

> پوشهٔ `.monta/` و `monta-question-bank.zip` به‌دلیل حجم زیاد در git نیستند. برای داشتن بانک منتا روی سیستم جدید، آن‌ها را یک‌بار کپی کنید (یا زیپ را کنار مخزن باز کنید) و دوباره `bun run db:sync` بزنید.

## گزینهٔ `--reset`

اگر دیتابیس فعلی دادهٔ غیرهم‌خانواده دارد (مثلاً seed قدیمی با UUIDهای متفاوت)، merge ممکن است به‌خاطر ناسازگاری کلیدهای خارجی شکست بخورد. در این حالت بازسازی کامل:

```bash
bun run db:sync --reset
```

این گزینه اول از `.data/pg` بکاپ زمان‌دار می‌گیرد (مثل `.data/pg.backup-20261117-...`)، بعد دیتابیس را از صفر می‌سازد.

## نکته‌ها

- **زمان‌بندی مدرسه و مطالعه** — مدرسه تا حدود ۱۵:۳۰ و پنج زنگ است؛ دانش‌آموز پایهٔ دوازدهم چهار روز و بقیه پنج روز مدرسه دارند. پنجرهٔ مطالعهٔ روزهای مدرسه از ۱۵:۳۰ تا ۲۰:۰۰ است (۳ زنگ) و روزهای تعطیل صبح و بعدازظهر (۳ تا ۴ زنگ). برنامه‌ها از همین پنجره‌ها و با همان فصل‌های منابع ساخته می‌شوند.
- **قبل از اجرا سرور را خاموش کنید.** PGlite اجازهٔ باز‌شدن همزمان یک دیتادیر توسط دو پروسه را نمی‌دهد؛ اسکریپت هم اگر `postmaster.pid` زنده‌ای پیدا کند، اجرا را متوقف می‌کند.
- خروجی `db:export:example` همیشه نباید دستی ویرایش شود؛ اگر دادهٔ دمو تغییر کرد، export را دوباره بگیرید (تغییرات گروه‌بندی فعلی همین‌طور در JSONها اعمال شده است).
- برای خروجی گرفتن دوباره از داده‌های فعلی: `bun run db:export:example`
